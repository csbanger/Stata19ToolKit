A full stop is Stata’s symbol for a missing value. It is not zero, and it is not an error.

Two consequences worth knowing. First, commands quietly skip missing values, so your Obs count can be lower than your number of rows. Second, in a comparison Stata treats missing as larger than any number, so drop if price > 10000 also drops the missing ones. Write drop if price > 10000 & !missing(price) when that matters.

A log file is a recording of your session: every command you ran and everything Stata printed back, written to a file as it happens. The do-file is the questions; the log is the answers.

It is worth the one line it costs. You keep a record of the numbers you actually saw on the day, you can scroll back through output that has long since gone from the Results window, and some courses ask you to submit one as evidence of your work.

Open it at the top of your do-file and close it at the bottom:

log using "week3.log", replace

sysuse auto, clear
summarize price

log close

replace overwrites yesterday’s log rather than refusing to start. Add , text for a plain file that anything can open, or use a .smcl name to keep Stata’s own formatting. See log in the dictionary.

Got log file already open? An earlier run never reached its log close. Run log close on its own, then start again.

Draw the graph, then export it on the very next line. Each new graph replaces whatever is in the Graph window, so exporting straight away is the habit that saves you redrawing things later. 

sysuse auto, clear

histogram mpg, frequency
graph export "figure1.png", width(1200) replace

width(1200) gives you something that still looks sharp in Word, and replace lets you rerun the do-file without an error. For a document you will print, a .pdf name keeps the lines crisp at any size; .png is the safe choice everywhere else.

The file lands in Stata’s working folder, which pwd will show you. From there it is an ordinary image: drag it into Word, or use Insert → Pictures. See graph export in the dictionary.

Right-clicking the Graph window and copying works for a quick look, but it copies at screen resolution and tends to come out blurry once printed.

Error messages

What Stata is actually telling you

Stata ends a failed command with a short message and a code in brackets, such as r(111). The code is just a label for the type of problem. These are the ones you will meet in your first term.

Scroll sideways on a narrow screen to see the fix column.
Message What it means What to do
variable price not found
r(111)		 Stata cannot see a variable by that name in the data currently in memory. Check you have loaded the data (describe), check the spelling, and check the capitalisation. lookfor pri finds variables whose names contain “pri”.
no observations
r(2000)		 The command ran, but your if condition matched no rows at all. Test the condition on its own with count if foreign == 1. A common cause is comparing against a value label (if foreign == "Foreign") rather than the number underneath it.
varlist required
r(100)		 The command needs you to name at least one variable, and you gave it none. Add the variables: summarize price mpg rather than bare summarize where a list is required.
invalid syntax
r(198)		 Stata got as far as reading your command and then could not make sense of the rest of the line. Check the comma before your options, check for unclosed brackets or quotation marks, and compare your line with the syntax diagram in help command.
file mydata.dta not found
r(601)		 Stata looked in its working folder and the file was not there. Run pwd to see where it looked, then cd into the right folder — or give the full path in quotation marks. Check the extension too.
no; dataset in memory has changed since last saved
r(4)		 You asked Stata to replace the data in memory, and it is protecting unsaved changes. Add clear to the command if you do not need those changes, or save first if you do.
price already defined
r(110)		 You used generate for a variable that already exists. Use replace to change an existing variable, or pick a new name. Stata separates the two on purpose so you cannot overwrite a column by accident.
type mismatch
r(109)		 You compared or combined text with a number. Quote text values (if make == "Honda"), and convert text that should be numeric with destring. describe shows which variables are str.
string variables not allowed A statistical command was handed a text variable it cannot work with. encode region, generate(region_num) turns categories into numbers with labels; destring handles numbers stored as text.
unrecognized command
r(199)		 Stata has never heard of the first word on your line. Nearly always a typo — sumarize, regres. If the command is one your course downloaded, install it with ssc install name.
too many variables specified
r(103)		 The command accepts fewer variables than you gave it. Check the syntax diagram in help. For example histogram takes exactly one variable, so plot them one at a time.
--more-- at the bottom of the screen Not an error. Older versions of Stata pause when output fills the window. Press the spacebar to continue, or run set more off once so it never pauses again.

Reading any error, not just these

Stata tells you where it stopped as well as why. The r(111) at the end of an error is a clickable link in the Results window: click it for the official explanation of that return code. And in a do-file, the command printed immediately above the error is the one that failed.

Decision helper

Which test should I use?

Answer two or three questions about your data and this will name the Stata command that fits, with a line you can copy. It gets you to the right command; whether that test is right for your question is still your course’s call.

The short version

One group, is the average different from a set number?
ttest — a one-sample t-test, e.g. ttest score == 50.
Two separate groups, is the average different?
ttest with by(), e.g. ttest price, by(foreign). If the numbers are badly skewed, ranksum instead.
The same people measured twice
ttest comparing the two columns, e.g. ttest before == after.
Three or more groups
oneway for one grouping variable, anova when you have more than one.
Two numbers, do they move together?
correlate to describe the link, regress to predict one from the other.
Two categories, are they related?
tabulate ..., chi2, e.g. tabulate foreign rep78, chi2.
A proportion, against a value or between two groups
prtest, e.g. prtest foreign == 0.3.
Predicting a yes/no outcome
logit, e.g. logit foreign mpg weight.

Read this before you quote it

Every test carries assumptions — roughly normal data, similar spread between groups, independent observations — and this helper cannot check any of them against your dataset. It narrows twenty commands down to one. Your lecture notes decide whether that one is defensible.

Glossary

The words, in plain English

Short working definitions for the terms that turn up in Stata output and in your lectures. They are deliberately informal; where your course defines something more precisely, your course wins.

Observation
One row of your data: one person, one car, one country, one year. Stata calls the count of them N or Obs.
Variable
One column: one thing measured about every row, such as price or age. describe lists the ones you have.
Categorical and continuous
A categorical variable puts each row in a group (pass or fail, north or south). A continuous one measures an amount that could in principle take any value in a range (price, height). Which one you have decides which commands and graphs make sense.
Sample and population
The population is everyone you want to say something about; the sample is the part of it you actually measured. Statistics is the business of saying something about the first using only the second — which is why almost every answer comes with an admission of uncertainty attached.
Mean
The ordinary average: add everything up and divide by how many. Sensitive to extreme values, so one millionaire drags the mean income of a village upwards.
Median
The middle value when you line everything up in order. Half the rows are above it, half below. Unbothered by extremes, which is why it is the better summary of skewed things like income or house prices. summarize, detail shows it.
Standard deviation
How spread out the values are, in the same units as the data. Small means everyone is bunched near the average; large means they are scattered. Two groups can share a mean and look nothing alike.
Standard error
Not the spread of your data but the wobble in your estimate: how much the mean would jump around if you took your sample again. Bigger samples give smaller standard errors, which is the whole argument for collecting more data.
Normal distribution
The symmetrical bell-shaped curve. Lots of tests assume your data is roughly this shape. “Roughly” is doing real work there — a histogram is usually enough to tell whether you are anywhere near it.
Skew
A distribution with a long tail on one side. Right-skewed (the common case) means a few very large values stretch the top end, which is what you are seeing whenever the mean sits well above the median.
Outlier
A value far away from the rest. Sometimes a real and interesting case, sometimes a typo with two extra zeros. Look at the Min and Max in summarize before you believe any result.
Missing value
A gap where no value was recorded, shown as a full stop. Stata leaves those rows out of any calculation involving that variable, which is why your Obs count can shrink without warning. misstable summarize finds them.
Null hypothesis
The boring explanation that your test is trying to rule out: there is no difference, no effect, no relationship. Tests are built to see whether your data is awkward enough to make that story hard to believe.
Alternative hypothesis
The claim you are entertaining instead: there is a difference. Two-sided means you would accept a difference in either direction, and it is what Stata reports by default on the Ha: diff != 0 line.
p-value
The chance of seeing a result at least this striking if the null hypothesis were true. Small means your data would be surprising in a world with no real effect. It is not the probability that your hypothesis is correct, and nothing in the number tells you the effect is large or important.
Significance level (alpha)
The threshold you agree on before looking, almost always 0.05. A p-value below it gets called statistically significant. The line is a convention, not a law of nature: 0.049 and 0.051 are practically the same result.
Statistically significant
Means only “unlikely to be chance alone”. It does not mean large, important, or useful. A tiny, meaningless difference becomes significant in a big enough sample.
Confidence interval
A range of plausible values for the thing you are estimating, usually at 95%. Read it as the honest version of your answer: not “the difference is $312” but “somewhere between −$1,500 and $2,100”. A wide interval that straddles zero is telling you the same thing a large p-value is.
Degrees of freedom
Roughly, how much independent information you have left after estimating things, often your sample size minus one. You rarely have to calculate it — Stata prints it, and it mostly matters because it shapes the test's comparison curve.
Correlation
A number from −1 to 1 saying how tightly two variables move together. Positive: both rise together. Negative: one rises as the other falls. Zero: no straight-line relationship — which is not the same as no relationship. correlate computes it.
Coefficient
In a regression, the number attached to a variable: how much the outcome changes when that variable goes up by one, holding the others fixed. Quote it in real units (“about $239 lower per mile per gallon”), not as a bare number.
R-squared
The share of the variation in your outcome that the model accounts for, from 0 to 1. Useful as a rough sense of fit. A low R-squared is not automatically a bad model, and a high one is not proof of anything.
Association and causation
Association means two things move together. Causation means one makes the other happen. Observational data can show the first and almost never proves the second, so write “is associated with” unless your design genuinely earns stronger language.
When nothing works

The ten-minute checklist

Before you email a tutor or start again from scratch, go down this list. It resolves the large majority of beginner problems.

  1. Is there any data loaded? Run describe. If it reports no variables, every other error is a consequence of that. Load your data first.
  2. Are you in the right folder? Run pwd. If it is not your course folder, cd there before doing anything else.
  3. Is the variable name exactly right? Stata is case-sensitive and will not guess. Click the name in the Variables window instead of typing it, or find it with lookfor.
  4. Did you use two equals signs in your condition? if price == 5000 compares; if price = 5000 is an error.
  5. Does the condition match anything? count if your condition will tell you. Zero explains a great many strange results.
  6. Is the Data Editor still open? With your data open for editing, Stata can refuse to run anything else. Close that window and try again.
  7. Is a variable text when it should be a number? describe shows str types. Fix with destring or encode.
  8. Have you actually read the error? It is short and it is usually literal. variable x not found means exactly that, nothing more subtle.
  9. Does your line match the official syntax? help command shows the syntax diagram and worked examples. Square brackets in it mean optional.
  10. Still stuck? Start clean. clear all, then run your do-file from the top. Leftovers from earlier commands cause problems that look impossible to diagnose.

If it is still broken

Ask for help with three things: the exact command you ran, the exact error message including the r(…) code, and what you expected to happen. That turns a twenty-minute conversation into a two-minute one.

Your tutor or lab demonstrator would rather answer a question in week two than read a broken assignment in week ten.
