Beginner Guide

Seven short lessons that take you from never having opened Stata to running a real analysis and explaining what it means. No prior statistics or programming needed, and every example uses a dataset that is already inside Stata, so you can follow along from the very first line.

Lesson progress Tick lessons off as you go — this browser remembers.

Before you start

You are not behind, and you are not bad at this

Stata looks unwelcoming the first time: a blinking cursor, no obvious buttons, and error messages written for people who already know what they mean. That is a problem with the software's manners, not with you.

Work through the lessons in order with Stata open beside this page. Each one takes about five minutes, ends with a question so you can check it landed, and has a button to tick it off. Nothing you type can break anything.

  • Every example runs on auto, a small dataset of 1978 cars that ships inside Stata.
  • Command names link to the Command Dictionary if you want more detail.
  • Use the copy button on each code block. Typos cause most beginner errors.

Why we use do-files from Lesson 1

Stata gives you a Command window where you can type one line at a time. It works, and almost every beginner starts there. We are going to skip it, and here is why.

A do-file is just a text file with your commands in it, in order. Typing into the Command window is like doing your working on a napkin; a do-file is doing it in your exercise book.

  • You can run it again. Found a mistake in step two? Fix that line and rerun everything in one click.
  • You can hand it in. Many courses ask for the do-file as well as the answers.
  • It is your memory. In week nine, the file tells you exactly what you did in week two.
  • Mistakes stop being scary. Your raw data is never touched, so the worst case is running the file again.

The Command window still has one good use: trying a single line you are unsure about. Once it works, paste it into your do-file.

The seven lessons

  1. Open Stata and write a do-file
  2. Load a dataset
  3. Look at your data

About 35 minutes in total. Stop whenever you like; your ticks are saved.

Lesson 1

Open Stata and write your first do-file

Goal: open Stata, work out what the windows are for, and save two working lines of code in a file you can run again tomorrow.

Steps

  1. Open Stata. On a lab machine or university virtual desktop it will be in the applications list. Use that version if you have one — it is the one your coursework was written for.
  2. Find the four windows. The screen is busy, but it is only four panels, each with one job.
    Command
    The single line where you can type one command at a time. We will barely use it.
    Results
    The big panel where output appears. It scrolls, so nothing is ever lost — scroll up.
    Variables
    A list of the columns in whatever data you have loaded. Empty until Lesson 2.
    History (or Review)
    Every command you have run this session. Click one to put it back in the Command box.
  3. Open the Do-file Editor. Use the menu (Window → Do-file Editor → New Do-file) or type doedit in the Command window and press Enter. A blank text window opens. This is where you will work from now on.
  4. Type the four lines below into the editor. Lines starting with * are notes to yourself; Stata ignores them completely.
  5. Save it as lesson1.do in whatever folder you are keeping this course in.
  6. Run it. Press the Execute button in the editor's toolbar (on Windows, Ctrl + D; on a Mac, Cmd + Shift + D).

The code

* lesson1.do
* My first Stata do-file

sysuse auto, clear
summarize price

What you should see

The Results window echoes each command back to you with a dot in front of it, then prints this table: 

    Variable |        Obs        Mean    Std. dev.       Min        Max
-------------+---------------------------------------------------------
       price |         74    6165.257    2949.496       3291      15906

The Variables window on the left has also filled up with names like make, price and mpg. That is your data.

Nothing appeared? Check you pressed Execute rather than just saving, and that the editor window was the active one.

Check your understanding

Your friend says they will just type their commands into the Command window instead. Give them one reason to use a do-file.

Any of these counts: you can run the whole analysis again after fixing one line; you can hand the file in; you can read it in two months and know what you did; and if you break your data you simply run the file again from the top. Typing in the Command window leaves no record once Stata closes.

Lesson 2

Load a dataset

Goal: get data into Stata and be sure it arrived — both the practice dataset we use here and, later, a file of your own.

Steps

  1. Start a new do-file for this lesson and save it as lesson2.do. One file per lesson keeps things tidy.
  2. Begin with clear all. It empties anything left over from last time, so today's results cannot be contaminated by yesterday's data.
  3. Load the practice data with sysuse. The clear on the end tells Stata it may throw away whatever was already in memory.
  4. Check it arrived. count tells you how many rows you have. If this prints 74, the data is in.
  5. When you come to use your own data, only one line changes. The last three lines of the code are commented out with *; delete the star from whichever one matches your file.

The code

* lesson2.do

clear all
sysuse auto, clear
count

* --- For your own data later on ---
* cd "C:/Users/you/Documents/stata19"
* use "mydata.dta", clear
* import delimited "mydata.csv", varnames(1) clear

What you should see

. sysuse auto, clear
(1978 automobile data)

. count
  74

Seventy-four cars. The note in brackets is just the dataset's own label, and the Variables window now lists twelve variables.

Got no; dataset in memory has changed since last saved? You left off the clear. Stata is protecting unsaved work rather than telling you off.

Check your understanding

You run use "mydata.dta", clear and Stata says the file is not found, but you can see the file sitting on your desktop. What is most likely wrong?

Stata is looking in a different folder. It has one “working folder” and only looks there unless you give a full path. Run pwd to see where it is looking, then cd into the right folder, or write the whole path in quotation marks. This is the single most common “file not found” cause, and it is never a missing file.

Lesson 3

Look at your data before you analyse it

Goal: find out what is actually in the dataset — which variables, what type they are, and where the gaps are — before you calculate anything.

Steps

  1. Run describe first. It lists every variable with its type. The type matters: a variable stored as str is text, and statistical commands will refuse it.
  2. Look at the actual rows with list. Always add in 1/10 or you will print all 74 rows — and in real data, thousands.
  3. Check for gaps with misstable summarize. Missing values in Stata show as a full stop, and they quietly shrink your sample later.
  4. Get to know one variable properly with codebook, which reports its range, how many values are missing, and how many distinct values it takes.
  5. Optional but pleasant: type browse in the Command window to see the data as a spreadsheet. Close that window before running anything else.

The code

* lesson3.do

clear all
sysuse auto, clear

describe
list make price mpg in 1/10
misstable summarize
codebook rep78

What you should see

describe reports 74 observations and 12 variables, and tells you that make is str18 — text — while the rest are numbers.

misstable summarize prints a short table naming only the variables with gaps. In auto there is exactly one: 

                                                 Obs<.
                                  +------------------------------
                                  |  Unique
         Variable     Obs=.   Obs>.   Obs<.   values        Min         Max
   -----------------+-----------------------------------------------------
            rep78        5              69        5          1           5

Five cars have no repair record. That is not an error and you do not need to fix it — but it explains why rep78 will show 69 observations later while everything else shows 74.

Check your understanding

describe says 74 observations, but when you summarise rep78 the Obs column says 69. Have you lost five cars?

No. All 74 cars are still there; five of them simply have no value recorded for that one variable. Stata skips missing values rather than guessing, so any statistic about rep78 is based on the 69 cars that have one. Always read the Obs column — it is how you notice this.

Lesson 4

Calculate summary statistics

Goal: produce the numbers that describe your variables, and know what every column of the output means.

Steps

  1. Start with summarize, the command you will use more than any other. It gives you the count, the mean (the average), the standard deviation (how spread out the values are) and the smallest and largest values.
  2. Add , detail when you want the median and the percentiles. The plain version does not show the median, which surprises everyone once.
  3. Count categories with tabulate. Use this for variables with a handful of values, such as foreign, rather than summarize.
  4. Compare groups by putting bysort in front of a command. It runs that command once for each group — the single most useful idea in Stata.

The code

* lesson4.do

clear all
sysuse auto, clear

summarize price mpg
summarize price, detail
tabulate foreign
bysort foreign: summarize price

What you should see

    Variable |        Obs        Mean    Std. dev.       Min        Max
-------------+---------------------------------------------------------
       price |         74    6165.257    2949.496       3291      15906
         mpg |         74     21.2973    5.785503         12         41

Reading that across:

  • Obs — how many cars had a value. 74 means none are missing.
  • Mean — the average price, about $6,165.
  • Std. dev. — roughly how far a typical car sits from that average.
  • Min and Max — the cheapest and dearest cars, and your best early warning of a typo in the data.

summarize price, detail adds the median, which comes out around $5,000 — noticeably below the mean. tabulate foreign shows 52 domestic cars and 22 foreign ones.

Check your understanding

The mean price is about $6,165 but the median is about $5,000. What does that gap tell you about the cars, and which number would you report?

A mean well above the median means the expensive cars are stretching the top end: most cars are cheap, a few are very dear. Statisticians call that right-skewed, which only means the long tail is on the right.

For a typical price, the median is the more honest summary. Reporting both, and saying why they differ, is better still.

Lesson 5

Make your first graph

Goal: draw a histogram and a scatterplot, and save one as an image file you could put in a report.

Steps

  1. Draw a histogram of one variable to see the shape of its distribution. frequency makes the height a simple count, which is easier to explain than the default.
  2. Save it straight away with graph export. Each new graph replaces the last one on screen, so export before you draw the next.
  3. Plot two variables together with scatter. The vertical axis variable comes first, which is the opposite way round from how most people say it aloud.
  4. Add a line of best fit by layering twoway plots in brackets. The /// at the end of a line just means “this command continues below”.

The code

* lesson5.do

clear all
sysuse auto, clear

histogram mpg, frequency normal title("How far these cars go on a gallon")
graph export "lesson5_histogram.png", width(1200) replace

twoway (scatter price mpg) (lfit price mpg), ///
       title("Price against mileage") legend(off)
graph export "lesson5_scatter.png", width(1200) replace

What you should see

A Graph window opens with your histogram: a row of bars, most cars bunched between roughly 15 and 25 miles per gallon, with a thin normal curve drawn over the top for comparison. Then it is replaced by the scatterplot: 74 dots with a straight line sloping downwards through them, because cars that do more miles per gallon tend to be cheaper.

In the Results window you also get a quiet confirmation for each export: 

file lesson5_histogram.png saved as PNG format

Where did the file go? Into Stata's working folder. Run pwd to find out where that is.

Check your understanding

You draw a histogram, then a scatterplot, and then run graph export "figure1.png", replace. Which graph ends up in the file?

The scatterplot. graph export saves whatever is in the Graph window right now, and each new graph command replaces what was there. Export each graph immediately after you draw it — which is exactly why the code above has an export line after every plot.

Lesson 6

Run a simple hypothesis test

Goal: compare two groups with a t-test, and find the one number everyone will ask you about.

A hypothesis test answers one narrow question: could a difference this big have turned up by chance, if there were really no difference at all? That is all it does. Here we ask whether foreign and domestic cars differ in price.

Steps

  1. Look at the groups first. tabulate foreign tells you how many cars are in each, and bysort gives you the two averages. Never run a test before you have seen the numbers it is testing.
  2. Run the test with ttest. The variable you are comparing comes first; by(foreign) says which variable splits the two groups.
  3. Find the p-value. Stata prints three at the bottom. The middle one, labelled Ha: diff != 0, is the ordinary two-sided test and almost certainly the one your course wants.
  4. Compare it with 0.05, the threshold most courses use. Below it, the difference is called statistically significant; above it, it is not.

The code

* lesson6.do

clear all
sysuse auto, clear

tabulate foreign
bysort foreign: summarize price

ttest price, by(foreign)

What you should see

A table with one row per group, then the difference between them, and underneath it three lines of p-values. The parts that matter:

  • The two group means: domestic cars average roughly $6,070 and foreign cars roughly $6,385.
  • The difference between them: a few hundred dollars.
  • The two-sided p-value on the Ha: diff != 0 line: around 0.68.

0.68 is a long way above 0.05. In plain English: a price gap this small, in a sample this size, is entirely unremarkable. We have not found evidence that the two kinds of car differ in price.

This is a perfectly good result. “No significant difference” is an answer, not a failed experiment — and it is far more common in real work than coursework examples suggest.

Check your understanding

Your p-value is 0.68. Which of these can you write — “foreign and domestic cars cost the same”, or “we found no evidence that they differ in price”?

The second. A large p-value means your data is consistent with there being no difference — but it is also consistent with a real difference that this sample of 74 cars was too small to detect. Absence of evidence is not evidence of absence, and markers notice the difference between those two sentences.

Lesson 7

Say what the output means, in plain English

Goal: turn a screen of Stata numbers into two or three sentences you could put in a report — which is what you are actually marked on.

Running the command is the easy half. The marks are in the sentence afterwards. Here is a pattern that works for almost any result: what you did, what you found, how sure you are, and what it means for the question.

Steps

  1. Run one more analysis — a regression, which asks how one variable moves with another. regress takes the thing you are explaining first, then the thing doing the explaining.
  2. Find three numbers: the coefficient on mpg, its p-value in the P>|t| column, and the R-squared at the top right.
  3. Say what the coefficient means in the units of your data: one more mile per gallon goes with a price lower by that many dollars.
  4. Write the sentences using the four-part pattern. Keep the hedging honest: associated with, not causes.

The code

* lesson7.do

clear all
sysuse auto, clear

summarize price mpg
regress price mpg

What you should see

A coefficient table. The mpg row shows a negative coefficient of roughly −239, its p-value is well under 0.05, and the R-squared near the top right is about 0.22.

Written out, that becomes:

A sentence you could hand in

“Using the 74 cars in the auto dataset, we regressed price on fuel economy. Each additional mile per gallon is associated with a price lower by about $239 (p < 0.05), and fuel economy alone explains around 22% of the variation in price.”

Notice what that sentence does not say: that better fuel economy causes lower prices. Cheaper cars are smaller and lighter, and lighter cars use less fuel. The regression cannot tell those stories apart.

Check your understanding

A classmate writes: “The regression proves that making a car more fuel efficient reduces its price.” What two words would you change, and why?

“Proves” and “reduces”. A regression on observational data shows an association, not proof and not cause. Something else — size and weight, here — plausibly drives both. Write “is associated with a lower price” and you are both accurate and unarguable.

Where to go next

You can now load data, inspect it, describe it, draw it, test it and explain it — from a file you can rerun. That is the whole shape of an introductory statistics assignment.

Keep the Command Dictionary open in a tab while you work; it is built for looking things up mid-task. When something breaks, the Help Centre translates Stata's error messages. And inside Stata, help followed by a command name is always the official answer for your version.

One last habit worth keeping: start every do-file with clear all, and run it from the top before you hand anything in. If it runs clean from an empty Stata, your results are real.
